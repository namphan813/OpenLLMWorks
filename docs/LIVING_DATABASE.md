# Living Database

## Vision

OpenLLMWorks is not simply a benchmark database.

It is a living historical record of local AI hardware performance.

Every benchmark submission expands the community's understanding of hardware capabilities while preserving a permanent snapshot in time.

Unlike traditional benchmark websites that primarily display rankings, OpenLLMWorks aims to tell the ongoing story of local AI.

---

# Philosophy

The homepage should answer one question every time someone visits:

> **"What has changed?"**

Every significant submission, milestone, or historical achievement should automatically surface through the website.

The database itself becomes the content creator.

---

# Dynamic Homepage

The homepage should evolve as new benchmark submissions are added.

Instead of static content, visitors should see information generated directly from the database.

Examples include:

- New hardware records
- Community milestones
- Historical firsts
- Interesting statistics
- Emerging hardware trends

No manual editing should be required.

---

# Community Story

The Community Story section highlights the single most interesting event occurring within the database.

Examples:

- The first Intel Battlemage GPU submitted
- NVIDIA surpasses 100 verified submissions
- AMD becomes the fastest average tg128 platform
- First Apple Silicon benchmark
- Fastest laptop GPU ever recorded

Only one story is displayed at a time.

The goal is to encourage repeat visits and highlight meaningful developments.

---

# Latest Activity

A continuously updating timeline showing recent benchmark activity.

Examples:

RTX 4070 submitted

Intel Arc B580 verified

RTX A2000 benchmark imported

Driver update improves RTX 3060 performance

This section reflects the pulse of the community.

---

# Interesting Facts

Automatically generated observations based on the current database.

Examples:

Fastest GPU

Most common CPU

Average VRAM

Largest RAM configuration

Highest tg128

Most efficient GPU

Every fact should include a timestamp indicating when the observation was generated.

Example:

Data Snapshot

As of March 22, 2027 14:35 UTC

Facts should always represent the current state of the database.

---

# Community Milestones

Celebrate meaningful achievements as the database grows.

Examples:

100 benchmark submissions

250 verified systems

First dual-GPU workstation

First ARM desktop

First Blackwell GPU

First Strix Halo APU

These milestones reinforce that the community is building something larger together.

---

# Historical Preservation

Historical information should never be overwritten.

Instead:

Current record

↓

Historical snapshot

↓

Trend analysis

↓

Long-term archive

The database should preserve not only today's fastest hardware but also how performance evolved over time.

---

# Data First

Every number displayed on the website should originate from the benchmark database whenever possible.

The website should become a presentation layer rather than a separate source of truth.

---

# Future Intelligence

Eventually the Living Database should identify meaningful events automatically.

Potential examples include:

- New hardware families
- Performance regressions
- Driver improvements
- Model compatibility improvements
- Efficiency gains
- Cost-per-token leaders
- Long-term performance trends

Rather than simply reporting data, OpenLLMWorks should interpret the database and surface insights for the community.

---

# Long-Term Goal

Visitors should return to OpenLLMWorks not only to compare hardware, but to discover what is happening across the world of local AI.

The database grows.

The website evolves.

The historical record is preserved.
